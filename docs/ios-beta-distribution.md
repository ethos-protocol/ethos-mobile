# iOS Beta Distribution via TestFlight (#461)

Automates external beta distribution for the iOS app via TestFlight. Each push to `main`
builds a signed Release IPA, uploads it to TestFlight, notifies the configured tester
groups, and attaches build notes generated from conventional commits since the last tag.

- Workflow: [`.github/workflows/ios-beta-distribution.yml`](../.github/workflows/ios-beta-distribution.yml)
- Lane: `ios/EthosProtocol/fastlane/Fastfile` → `ios beta_distribution`
- Release notes: [`.github/scripts/generate_release_notes.py`](../.github/scripts/generate_release_notes.py)

For the full App Store release pipeline (internal TestFlight + review submission) see
[ios-app-store-release.md](ios-app-store-release.md).

## How a beta distribution flows

```
push to main ──► beta-distribution job (macos-26, Xcode 26.6)
                  1. validate: version, release notes from commits
                  2. xcodegen → match (read-only) → build_app (Release, TLS pins)
                  3. verify TLS pins in the built Info.plist (check_tls_pinning.py)
                  4. upload_to_testflight:
                       distribute_external: true
                       groups: [beta-testers, ...]   ← TESTFLIGHT_BETA_GROUPS variable
                       notify_external_testers: true
                       expire_previous_builds: true  ← when BETA_EXPIRY_DAYS < 90
                       changelog: <generated from commits>
```

Testers in the named groups receive an email from Apple with a TestFlight install link.

## Secrets and variables

### Required secrets

| Secret | Description |
| --- | --- |
| `ASC_KEY_ID` | App Store Connect API key ID |
| `ASC_ISSUER_ID` | App Store Connect issuer ID |
| `ASC_KEY_P8_BASE64` | Base64-encoded `.p8` API key content |
| `MATCH_GIT_URL` | Git URL for the match certificate repository |
| `MATCH_PASSWORD` | Encryption passphrase for match certificates |
| `ETHOS_CERT_PINS` | Comma-separated TLS pin list (current,backup SPKI SHA-256) |

### Optional secrets

| Secret | Description |
| --- | --- |
| `MATCH_GIT_BASIC_AUTHORIZATION` | `base64(user:token)` — required when `MATCH_GIT_URL` is HTTPS |
| `BETA_FEEDBACK_EMAIL` | Email address testers send feedback to (shown in TestFlight) |

### Repository variables

| Variable | Default | Description |
| --- | --- | --- |
| `APPLE_TEAM_IDENTIFIER` | *(required)* | Apple Developer Team ID (e.g. `ABCDEFGHIJ`) |
| `TESTFLIGHT_BETA_GROUPS` | `beta-testers` | Comma-separated TestFlight external group names |
| `BETA_EXPIRY_DAYS` | `30` | Days before a beta build is removed from the group (1-90) |

### Setting up TestFlight tester groups

1. In App Store Connect, go to **TestFlight > External Testing > Add External Testers Group**.
2. Create groups such as `beta-testers`, `qa-team`, or `partners`.
3. Add testers to each group. Testers receive an invitation email from Apple.
4. Set `TESTFLIGHT_BETA_GROUPS` to the comma-separated names (e.g. `beta-testers,qa-team`).

Testers in external groups must accept Apple's beta testing agreement (a one-time step per app).

## Build expiry

TestFlight builds expire **90 days after upload** (Apple's fixed limit). The `BETA_EXPIRY_DAYS`
variable controls how long builds remain visible in each tester group:

- When `BETA_EXPIRY_DAYS < 90`, the lane sets `expire_previous_builds: true`, which removes
  older builds from the group when the new build is distributed. This keeps the tester view
  clean without waiting for Apple's 90-day hard expiry.
- Set to `90` to keep all builds visible until Apple removes them automatically.

## Build notes from commits

Release notes are generated by `.github/scripts/generate_release_notes.py` from conventional
commits (`feat:`, `fix:`, `perf:`) since the last `vX.Y.Z` tag. The iOS App Store 4000-char
limit applies. To override, either:

- Set the `release_notes` input on a manual workflow run, or
- Commit a hand-written override to `ios/EthosProtocol/fastlane/release_notes/<version>/en-US.txt`.

## Workflow inputs (manual dispatch)

| Input | Default | Effect |
| --- | --- | --- |
| `dry_run` | **true** | Validates config, makes an unsigned Release build, prints what would be uploaded; signs and uploads nothing. |
| `groups` | *(from variable)* | Override the tester groups for this run only. |
| `expiry_days` | *(from variable)* | Override the expiry for this run only. |
| `release_notes` | *(generated)* | Override build notes for this run only. |

## Maintainer checklist (first-time setup)

- [ ] Add all required secrets to the repository (Settings > Secrets and variables > Actions).
- [ ] Set `APPLE_TEAM_IDENTIFIER` as a repository variable (it is already required by `ios-applinks-verify.yml`).
- [ ] Create at least one external testing group in App Store Connect and set `TESTFLIGHT_BETA_GROUPS`.
- [ ] Run the workflow manually with `dry_run: true` and verify the step summary shows the correct version, groups, and notes.
- [ ] Run with `dry_run: false` to upload the first real beta build.
- [ ] Verify invited testers receive the TestFlight notification email.
